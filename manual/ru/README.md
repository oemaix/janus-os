# Janus OS

Janus OS не поставляет готовую систему маршрутизатора. Её собираете вы
сами: образ на одном компьютере, затем запись на небольшую плату.
Образ — это NixOS. Плата не собирает программы и не вычисляет Nix.
Компьютеру, который собирает образ, нужен Nix с flakes. Сам он не
обязан быть NixOS.

Проект публичный и распространяется по лицензии Apache 2.0.

## Что можно сделать сейчас

Образ маршрутизатора загружается в виртуальной машине. Образы есть для
NanoPi R4S, Le Potato, Raspberry Pi Zero 2 W, Raspberry Pi 3 / 3+,
Raspberry Pi 4 и Compute Module 4, Raspberry Pi 2 v1.1, StarFive VisionFive 2 и Yanyu STX-R19F (Limine на
legacy BIOS). `janus` и `janus-build`
реализуют команды фазы 1, а также proxy, DNS, fleet, status, backup,
deploy и журнал соединений. Если в образе заданы `janus.access.web.enable`
и файл пароля, страница обслуживания слушает порт 8443. На плате `janus deploy` завершается с кодом 2
и называет `janus-build`. OLED-HAT Waveshare 1,3″ на Raspberry Pi Zero 2 W, Raspberry Pi 3 или
Raspberry Pi 4 показывает состояние. С панели можно обновить прокси,
выбрать узел, перезагрузить плату или стереть состояние. ИБП mcuzone на
этой плате может выключить её, пока элемент разряжается.

Для работы с исходным кодом есть оболочка разработки: в клоне этого
репозитория выполните `nix develop`. Для работы маршрутизатора этот
клон не нужен.

## Nix на сборочной машине

Этот проект — flake Nix. `nix run` и `nix flake` недоступны, пока Nix
не разрешит их в конфигурации.

Если машина не NixOS, сначала установите Nix:
<https://nixos.org/download/>.

Обычная установка оставляет команду Nix и flakes выключенными. Добавьте
эту строку в `/etc/nix/nix.conf`. Для однопользовательской установки
вместо этого используйте `~/.config/nix/nix.conf`:

```
experimental-features = nix-command flakes
```

После правки `/etc/nix/nix.conf` перезапустите службу:
`sudo systemctl restart nix-daemon`. В NixOS тот же переключатель
задаётся в конфигурации системы, после чего система пересобирается:

```nix
nix.settings.experimental-features = [ "nix-command" "flakes" ];
```

Если `nix flake --help` печатает справку, этот шаг уже сделан.

## Закрытый репозиторий флота

`janus-build` отдельно не устанавливается. Первая команда называет
flake Janus и создаёт закрытый каталог:

```
nix run github:oemaix/janus-os#janus-build -- init ./fleet
```

Локальный клон — та же команда, только вместо flake с GitHub указан
каталог:

```
nix run ./janus-os#janus-build -- init ./fleet
```

`init` принимает новый каталог, `./fleet`. Адреса flake он не
принимает. Этот адрес — цель `nix run`, и новый репозиторий закрепляет
тот же Janus. Дальше работа идёт внутри репозитория флота:

```
cd fleet
nix develop
```

После этого `janus-build` есть в `PATH`.

## Сборка и запись

В этой оболочке:

1. `janus-build host add <host>` задаёт имя одной платы.
2. Файл узла задаёт плату, WAN и хотя бы одну LAN. Порты берутся из
   профиля платы. Зафиксируйте этот узел в git.
3. `janus-build secret keygen <host>` создаёт ключ age этого
   маршрутизатора. Команда записывает открытый ключ в
   `secrets/keys/<host>.pub` и один раз печатает закрытый ключ. Сохраните
   закрытый ключ в менеджере паролей, например в KeePass. Сборочная
   машина копию не хранит, и ключ не попадает в git. Делайте это после
   появления узла и до сборки.
4. `janus-build secret set <path>` шифрует каждый секрет, который нужен
   этому узлу: пароль PPPoE, пароль Wi-Fi, адрес подписки или ручной
   узел. Открытый ключ из предыдущего шага уже должен существовать.
5. `janus-build build <host>` записывает `janus-<host>.img`. Образ
   содержит этот шифротекст. Закрытого ключа в нём нет.
6. Запишите этот образ на носитель. Раздел состояния поначалу пуст.
7. Входите по SSH как root с ключом из конфигурации узла. Входа по
   паролю нет.
8. Один раз установите закрытый ключ из менеджера паролей командой
   `janus-build deploy --age-key <host>` на сборочной машине.
   (На маршрутизаторе `janus secrets install-age-key` делает то же самое.)
   PPPoE, Wi-Fi и секретный адрес подписки недоступны до этого шага.
9. `janus proxy refresh` заполняет подписку из `urlSecret`. Пока ключ
    не установлен и это обновление не выполнено, снимок пуст.

Узел без зашифрованного секрета может пропустить ключ, `secret set` и
установку. LAN и SSH ключ age не требуют.

Имена параметров —
[docs/08-configuration-reference.md](../../docs/08-configuration-reference.md).
`janus-build check <host>` вычисляет конфигурацию и не собирает образ.

`janus.region` — это `cn` (по умолчанию), `ru` или `ir`. От него зависит
внутренний резолвер, а для `ru` ещё и отказ QUIC, который не попал в
прямое правило, пока не задан `janus.proxy.blockQuic`. Правила маршрутизации остаются пустыми, пока их
не запишут в конфигурацию. В примере активен список `cn`, рядом в
комментариях лежат `ru` и `ir`. У `ir` нет встроенного внутреннего
резолвера: задайте `janus.dns.domestic.resolvers`, шифрованный резолвер
для внутренних имён. Смена региона — это пересборка, не горячая замена.

## Повседневная работа

`janus status` на плате сообщает о работающей системе. Обновление
подписки, выбор узла и проверка DNS — это `janus proxy` и `janus dns`.

Эти изменения не требуют нового образа:

- адрес подписки, которая уже есть в образе
- статическая аренда в LAN, которая уже есть в образе, в том числе новое
  имя узла
- пароль сети Wi-Fi, которая уже есть в образе

`janus override show` показывает их. `janus-build fleet pull` записывает
аренды обратно в закрытый репозиторий. `janus-build fleet apply`
отправляет зафиксированные адрес подписки, пароль Wi-Fi и аренды. Всё
остальное в этом коммите остаётся для deploy.

## Новая система

Перезаписывайте `janus-<host>.img`, когда меняется разметка разделов.
`janus-build deploy --preserve-state <host>` сначала копирует набор
состояния на сборочную машину. Команда не записывает образ. После загрузки
нового образа `janus restore` возвращает этот архив.

`janus-build deploy <host>` копирует новое замыкание системы, обновляет
загрузочную запись и перезагружает плату. Когда плата поднялась, выполните
`janus-build deploy --confirm <host>`. Без подтверждения следующая
загрузка возвращает предыдущую загрузочную запись.

Слоты A/B выключены, пока образ не собран с
`janus.storage.slots.enable = true`. Запишите такой образ один раз.
Дальнейший deploy пишет другой слот корня и хранилища, затем меняет
загрузочную запись. Раздел состояния общий, поэтому переопределения и
ключ age остаются. Подтверждение то же. Если новые образы не помещаются
в слоты, зафиксированные при записи, deploy останавливается и просит новый
образ. Носитель, записанный без этой опции, не имеет второго слота, и
deploy об этом сообщает.

## Журнал соединений

Журнал выключен, пока в образе не задано
`janus.monitoring.audit.enable = true`. После загрузки такого образа
запись включена. `janus audit stop` ставит её на паузу без пересборки.
`janus audit start` включает её снова. Если образ собран без этого
переключателя, `janus audit start` завершается с кодом 2.

`janus audit status` печатает, идёт ли запись, путь, размер и самую
старую запись. `janus audit export` печатает журнал. Каждая строка — один
объект JSON: протокол, источник, назначение, порты, число байтов, начало,
конец и домен, если маршрутизатор его уже знает. Файл —
`/var/lib/janus/audit/connections.jsonl` на разделе состояния. Срок
хранения по умолчанию — 7 дней. Скопируйте журнал с платы, чтобы читать
его. Полезные данные пакетов не сохраняются, и плата журнал не
анализирует.

Пустой список интерфейсов проверяет проксируемые LAN.
`audit.interfaces` называет LAN, которые нужно проверять вместо этого.

## Страница обслуживания

Страница выключена, пока в образе не заданы
`janus.access.web.enable = true` и `janus.access.web.passphraseFile`.
После загрузки такого образа страница слушает порт 8443, только TLS,
в зонах `lan` и `mgmt`. `janus web stop` ставит её на паузу без
пересборки. `janus web start` включает её снова. Если образ собран без
этого ключа, `janus web start` завершается с кодом 2. Пустой файл
пароля даёт код 1.

Откройте `https://<адрес-lan>:8443/`. Сертификат самоподписанный.
Сверьте отпечаток на странице с `janus web fingerprint`, затем введите
пароль. Это не пароль root, и SSH остаётся только по ключу.

Страница показывает состояние, действия туннеля, WAN и аренды, горячие
переопределения, трафик и DNS, и перезагрузку. Остальную конфигурацию
она не меняет. Заводской сброс и уже сохранённые секреты она не
показывает.

## Панель состояния

OLED-HAT Waveshare 1,3″ на Raspberry Pi Zero 2 W, Raspberry Pi 3 или
Raspberry Pi 4 показывает состояние. В файле хоста периферия называется так:

```
janus.hardware.peripherals.panel = {
  class = "hmi";
  hmi.profile = "waveshare-1.3-oled-hat";
};
```

Джойстик меняет страницу и строку. Нажатие в центр подтверждает узел
туннеля. KEY1 выполняет `janus proxy refresh`. Удержание KEY3 три
секунды выполняет `janus reboot`. `hmi.keys.KEY1`, `hmi.keys.KEY2` и
`hmi.keys.KEY3` могут быть `refresh`, `reboot-hold`, `factory-reset` или
`unbound`. `factory-reset` выполняет `janus reset --state --yes`: раздел
состояния стирается, затем плата перезагружается. Панель не меняет
конфигурацию, горячие переопределения и секреты. Через минуту без ввода
экран гаснет; следующее нажатие открывает ту же страницу.

## Батарея

ИБП mcuzone Pi Zero на I²C `0x40` показывает элемент в `janus status`.
Пока элемент разряжается, маршрутизатор выключается, если напряжение
60 секунд остаётся не выше 3,50 В или 10 секунд остаётся не выше 3,30 В.
При загрузке уже разряжающийся элемент ниже 3,55 В выключает плату до
старта сети. Зарядка, ток в пределах 5 мА от нуля, отсутствующий датчик
и `power.shutdown.enable = false` оставляют маршрутизатор включённым.
Адрес Waveshare `0x43` не показывает показания и не выключает плату.

## Платы третьего уровня

Raspberry Pi 2 v1.1 (BCM2836) и StarFive VisionFive 2 — профили третьего
уровня. Raspberry Pi 2 v1.2 — это BCM2837, для него берётся профиль
Raspberry Pi 3. Эти два образа собираются кросс-компиляцией. Двоичного
кэша нет, поэтому первая сборка долгая. Для них
`janus.build.strategy` равен `cross`. Flake флота передаёт `buildSystem`
в `mkRouter`. У чистого вычисления нет текущей системы, поэтому запасной
вариант — `x86_64-linux`. `janus-build` на другой машине вычисляет flake
с системой этой машины и останавливается, если образ всё ещё назначен на
сборку в другом месте. Ставьте `emulated` только если сборочная машина
умеет выполнять эту архитектуру.

Образ Pi 2 — 32-битный. Загрузочный раздел — файловая система FAT,
которую читает прошивка платы. Образ VisionFive 2 кладёт SPL и U-Boot в
разделы GPT, которые ищет плата, и загружает ядро из `extlinux.conf`.
U-Boot сам выбирает дерево устройств для ревизии платы. Ни один из
профилей не назначает разъём WAN.

## Потоки и метрики

Экспорт потоков выключен, пока
`janus.monitoring.flows.export.collector` не станет именем хоста или
адресом IPv4. Протокол — `ipfix` (по умолчанию, порт 4739) или
`netflow9`. Janus отправляет потоки со всех WAN и со всех мостов LAN.
`janus.monitoring.interfaces` называет меньший набор: имена WAN, LAN,
порта, VLAN или Wi-Fi из конфигурации. Janus переводит их в имена
интерфейсов ядра, такие как `eth0`, `ppp-<wan>` и `br-<lan>`. Сборщик
обычно в `mgmt` или в LAN. Экспорт держит в памяти кольцо из 8192
потоков. Это не захват пакетов.

`janus.monitoring.prometheus.enable = true` слушает порт 9100 по IPv4 и
IPv6. Список зон по умолчанию — `mgmt`. Трафик на этот порт принимается
в этих зонах и отбрасывается на всех остальных интерфейсах, в том числе
на LAN с политикой входа accept. `prometheus.zones` меняет эти зоны.
Конечная точка — node exporter и
метрики движка: запущен ли движок, выбранный узел, его последняя
задержка, последнее успешное обновление подписки, последнее обновление
Geo и была ли ошибка этого обновления.

`janus.monitoring.scope = "flows"` само по себе не называет сборщик.
Задайте ещё `flows.export.collector`.

## Чего плата не делает

Плата не запускает `nixos-rebuild` и не вычисляет Nix. Структурные
изменения — это новый образ или deploy со сборочной машины. Список команд
на маршрутизаторе — [docs/14-cli.md](../../docs/14-cli.md). Список команд
на сборочной машине —
[docs/16-build-host-cli.md](../../docs/16-build-host-cli.md). Оборудование
и план по этапам — в [docs/](../../docs/README.md).
