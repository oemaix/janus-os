# 22 — Implementation tarpits

| Field | Value |
|-------|-------|
| Status | Draft |
| Version | 0.1.0 |
| Last updated | 2026-11-13 |

A tarpit is a failure that looks like progress until a later build or
boot. The binding choice stays in the cited document. This list is the
constraint that choice ran into.

Each row is `T-nnnn`. The number is assigned once and is not reused. A
deleted number is not reused. `open` means the tree still hits the row.
`kept` means the code follows it. A `kept` row stays, so the next change
does not undo it.

| # | State | Trap |
|---|-------|------|
| T-0001 | kept | `generate-config.pl` gets two passes. Answering `n` when the alternatives have no `n` repeats the question and then ends the script (`Error in reading or end of file`). A required answer for a symbol that was not asked fails with `error: unused option`. An optional unused answer is a warning. The arm64 defconfig patch in `modules/janus/system/kernel-profile.nix` exists because a `select` kept the SAS transport `y` after the HBAs were turned off. |
| T-0002 | kept | `select` holds the target at `y` or `m`. Turning the target off while the selector stays on is T-0001. Seen on 6.18: `HIBMCGE` selects `MOTORCOMM_PHY`, `USB_NET_HUAWEI_CDC_NCM` selects `USB_WDM`, and `NET_DSA_REALTEK` selects `REALTEK_PHY`. Turn the selector off, or keep the target. |
| T-0003 | kept | Nixpkgs sets some children as required answers. Once the parent is `n` they are not asked, and the required answer fails the build. Replace that answer with optional `n` (`lib.kernel.option lib.kernel.no`). A hidden symbol is ignored. `RTW88_8822BE` and `RTW88_8822CE` stay required while `WLAN` is on, because no allowlisted stick uses `RTW88`. Optional `n` applies whenever `RTW88` is off, not only when every Wi-Fi driver is off. |
| T-0004 | kept | `SATA_MOBILE_LPM_POLICY` is an integer. Nixpkgs sets freeform `"3"`. `n` is not a legal answer. When AHCI is off, set optional freeform `"3"` so the hidden symbol is not a required unused option. |
| T-0005 | kept | A boot MMC host that `boot.initrd.availableKernelModules` does not list stays built in. Forcing a defconfig `y` to `m` leaves the root disk with no driver in the initrd. Le Potato: `MMC_MESON_GX`, and the initrd lists `mmc_block` only. Zero 2 W SD card: `MMC_BCM2835` (`sdhost`). `boot.initrd.allowMissingModules` defaults to false. A listed name with no `.ko` fails the image build. A built-in driver has no `.ko`, so listing that name also fails. See D-0052 and *10* §3.6 and §4.7. |
| T-0006 | kept | On the Zero 2 W, `sdhci_iproc` (`MMC_SDHCI_IPROC`) is the Arasan radio, not the SD card. The initrd does not list it. An access point loads `sdhci_iproc` with `brcmfmac` from `boot.kernelModules`. That option is an attribute set applied with `attrNames`, so the order written in Nix is not the load order. See *10* §4.7. |
| T-0007 | kept | On the Pi 3 and Pi 3+, the SD card is `sdhost` (`MMC_BCM2835`) and stays built in. The initrd lists neither `bcm2835` nor `sdhci_iproc`. The Arasan host is the radio. The NixOS arm64 config answers `MMC_SDHCI_IPROC=m` even though `ARCH_BCM_IPROC=y`, so udev loads `sdhci_iproc` and `brcmfmac` requests firmware on a Pi 2 v1.2. The profile pins `n` until an access point sets `match.onboard`; then the symbol is `m`, stage 2 loads `sdhci_iproc` with `brcmfmac`, and the initrd still does not list it (T-0006). The boot files are `bcm2837-rpi-3-b.dtb` and `bcm2837-rpi-3-b-plus.dtb`. The Pi 4 card is the same symbol. Pin `y` on every image. Leaving the NixOS `m` makes the card wait for a module the initrd does not list. The Pi 2 initrd lists `bcm2835`, so that host is a module. See D-0052, D-0064, and *10* §3 and §4.12. |
| T-0008 | kept | `eval-kernel-profile` and `eval-kernel-profile-matched` read the Nix attribute set. `generate-config.pl` runs in `eval-kernel-config`. A symbol assertion can require `=m` for a host the initrd does not load (T-0005). A new file is invisible to the flake until `git add`. A dirty edit of a tracked file is visible. Adding the file is not a commit. |
| T-0009 | kept | Huawei `12d1:1506` in `ncm` binds `huawei_cdc_ncm`. That driver selects `cdc_ncm` and `USB_WDM`. Loading `cdc_ncm` alone does not bind the stick. Leaving `USB_NET_HUAWEI_CDC_NCM` at its defconfig value while `USB_USBNET` is on still selects `USB_WDM` (T-0002). See *10* §4.2 and D-0052. |
| T-0010 | kept | The Soloist URLs on the downloads page have no version and are replaced in place. `flake.lock` pins each archive (`soloist-x86_64`, `soloist-aarch64`, `soloist-armv7l`). `nix flake update` moves the narHash. An unpinned fetch follows the URL and can install a build that was not locked. A locked build expires 90 days after its build date and the program exits 10, and the unit does not restart on that status. Update the lock before then. See D-0058. |
| T-0011 | kept | `matched` answers `BT_HCIUART_SERDEV` with optional `n` while the UART parent is off. Onboard Bluetooth needs that symbol and `BT_HCIUART_BCM` at `y`, or the controller does not bind. Set both when `janus.audio.enable` is true and `playback.output` is `bluetooth`. Leaving `SERDEV` at `n` while `BT_HCIUART` is `m` looks configured and never probes. See D-0061. |
| T-0012 | kept | The ROCK Pi 4C blacklists `hci_uart`. Building `BT_HCIUART` does not start the onboard controller while that name is blacklisted. Drop the blacklist only when `janus.audio.enable` is true and `playback.output` is `bluetooth`. `btusb` stays available for a dongle. See D-0053 and D-0061. |
| T-0013 | kept | `bluetoothctl pair` without `--agent NoInputNoOutput` does not finish Just Works pairing. The command has no terminal to confirm a prompt. A `scan on` that exits before `pair` also drops a speaker that is only discoverable briefly. Keep that agent on pair and connect when no code was given, and leave the scan running until pair returns. A code starts `janus-bt-agent` for that address only, after the scan is up, and stops it before connect. The code is stdin. The agent accepts authorization for that address and confirms a shown number only when it is the code. It exits when its parent exits. `bluetoothctl` itself does not accept the code. |
| T-0015 | kept | `pair` by name must use devices that appeared in that search. `bluetoothctl devices` is the cache and still holds a speaker that is not nearby. Pairing the cached name connects the wrong device. `connect`, `disconnect`, and `remove` still use the cache, because those speakers are already known. |
| T-0016 | kept | The maintenance page has one Janet thread. `os/execute` stalls every fiber for the whole command, so discovery and pairing freeze status and login. Spawn the command and wait with `os/proc-wait`, which suspends only the fiber that asked. |
| T-0017 | kept | `janus-bluetooth` has no local variables. `parse_scan` and `find_name` run in the same shell. `parse_scan` must not assign `name`. That variable is the name the operator asked to pair. Overwriting it makes the scanned speaker match itself, so a request for a different name still pairs the nearby device. |
| T-0014 | kept | The system PipeWire socket is `/run/pipewire-0`. A client with no `PIPEWIRE_RUNTIME_DIR` looks under `XDG_RUNTIME_DIR` and does not open that socket. Soloist and `wpctl` need `PIPEWIRE_RUNTIME_DIR=/run`. The Bluetooth path has no `playback.node`, so a missed socket is silence. |
| T-0018 | kept | Turning `SOUND` back on in `matched` restores the architecture defconfig sound tree. Set that tree to optional `n` and module only the driver for the `janus.audio` device. `SND_MESON_CARD_UTILS` selects `SND_DYNAMIC_MINORS`, so that bool is `y` when the Le Potato card is on. `DRM_VC4` stays `n`: Pi HDMI depends on `SND` and the consoles are serial. Do not set `SND_SOC_ROCKCHIP`. Linux 6.18 has no such symbol. The defconfig name is stale. See D-0061. |
| T-0019 | kept | The Yanyu HDA controller needs a codec parser. `SND_HDA_CODEC_REALTEK` enables that menu. Its hidden `SND_HDA_CODEC_REALTEK_LIB` selects `SND_HDA_GENERIC`. Forcing the lib or the generic parser `n` leaves `SND_HDA_INTEL` with no PCM device. Do not put the lib in the off catalog. `ALC269` defaults to `y` under that menu. `SND_HDA_HWDEP` is a bool, so `m` repeats the question and `generate-config.pl` stops (T-0001). Set it `y`. See D-0061. |
| T-0020 | kept | `whisper.cpp` and Piper are flake inputs at release tags. Piper's repository is <https://github.com/OHF-Voice/piper1-gpl>. The old path is not the pin. The multilingual `base` file is `ggml-base.bin` from `ggerganov/whisper.cpp` on huggingface.co. Each voice file is the published Piper id on `rhasspy/piper-voices` there. `flake.lock` records the narHash. `nix flake update` moves it. A branch tip, a pull request, or an untagged commit of either program installs a build the definition does not name. An unpinned fetch does the same. See D-0062. |
| T-0021 | kept | `install -d -m 0755` on `/run/janus-http` makes that directory world-traversable. Speech body files are then readable. The lock directory is `/run/janus-http/lock` at mode `0700`. Do not chmod the runtime directory. The listener umask is `0077`. The socket stays `0660` so stunnel can connect. See D-0062. |
| T-0022 | kept | The speech lock exits 5, and the listener maps 5 to HTTP 409. `jq` exits 5 on invalid JSON, so a parse error must exit 4 or a bad body is `busy`. `if ! cmd; then exit $?; fi` exits 0 because `!` inverts the status. Save the status, then exit with it. See *14* §8. |
| T-0023 | kept | The bearer token is checked after the headers and before the body. Reading the body first lets a LAN client fill memory without the token. `janus-http` keeps `MemoryMax`: `128M` with speech off, `1536M` with recognition or synthesis on. Four calls may be in flight. Dropping the cap lets that client exhaust the router. See D-0062 and *08* §1c. |
| T-0024 | kept | `/run/janus-http/lock` at mode `0700` and owner `root` locks out `janus-http`. Microphone and playback then fail. The directory is created with `install -d -m 0700 -o janus-http -g janus-http`. Do not chmod `/run/janus-http`. See T-0021. |
| T-0025 | kept | An x86_64 eval check that string-interpolates the aarch64 Soloist package builds that derivation. The board strategy is emulated, so the builder is aarch64 (docs/09 §4). `autoPatchelf` skips an ELF of another architecture, so the package cannot move to the x86_64 stdenv. The GitHub runner has no binfmt and Nix stops: `Required system: 'aarch64-linux'`. Keep that store path out of the check unless the check's builder is aarch64. `eval-soloist-on` still runs the x86_64 binary. |
| T-0026 | kept | `eval-wifi-onboard-boards` string-interpolated `janus-hostapd-home`'s `ExecStart`. Pi and ROCK boards are emulated, so that script is an aarch64 derivation and pulls aarch64 `hostapd` (docs/09 §4). The GitHub runner has no binfmt and Nix stops: `Required system: 'aarch64-linux'`. Read the script text and drop its store context with `hostapdText`, as `eval-wifi-onboard` already does. See T-0025. |
| T-0027 | kept | NixOS leaves `boot.initrd.includeDefaultModules` true, so the initrd list gains `ahci`, `ata_piix`, `nvme`, the `sata_*` and `pata_*` drivers, and the USB HID set. `modules-shrunk` stops on the first name that is neither built in nor a `.ko`. `matched` answers `SATA_AHCI` with `n` except on the Yanyu, where the profile lists `ahci` and the symbol is `m`. `BLK_DEV_NVME` is `n` on the Zero 2 W, Le Potato, the Pi 4, and the Yanyu, and the NixOS list still names `nvme`. `ahci` sorts first, so the closure stops there. `boot.initrd.allowMissingModules` stays false (T-0005). The image sets `includeDefaultModules` false. Each board profile lists the modules its initrd loads, and the storage module adds `f2fs`, `vfat`, `nls_cp437`, and `nls_iso8859_1`. See *10* §3. |
| T-0028 | kept | Vendor `initrd.target` has `OnFailure=emergency.target`. `boot.initrd.systemd.emergencyAccess` would unlock sulogin for every failed initrd boot, including a state device that never appears. A failed probe, a failed resize, or a check that exits non-zero leaves the file. Do not start `emergency.target` from the check. See D-0068. |
| T-0029 | kept | Xray tproxy does not rewrite the packet destination port. | T-0032 | kept | With a LAN, sing-box sets `route.final` to `direct` and xray appends a final `tcp,udp` rule to outbound `direct`. | T-0033 | kept | `rtl8xxxu` has `0bda:8176` in its static USB id table. `remove_id` drops a dynamic id only, so an unbind lets that driver take the stick again. The netdev disappears, `BindsTo=` stops `janus-hostapd-*` with SIGTERM, and `Restart=on-failure` leaves it stopped. Set `driver_override` to `rtl8192cu` before the unbind. Read it back and unbind only when it reads `rtl8192cu`. A failed write must not unbind. Retry that bind about once a second while the driver is not `rtl8192cu`.
